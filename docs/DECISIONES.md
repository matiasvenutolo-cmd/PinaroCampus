# Decisiones

Registro de decisiones tomadas durante la implementación que no están en la especificación. Formato: fecha · decisión · motivo · cómo revertirla.

| Fecha | Decisión | Motivo | Reversión |
|---|---|---|---|
| 2026-09-27 | Auth.js v5 (`next-auth`) fijado en `5.0.0-beta.32`, aunque nunca salió de beta | Es la única versión que soporta sesiones en base vía adapter de Drizzle + `trustHost` dinámico por dominio, tal como pide `02-arquitectura.md`; está ampliamente usada en producción pese al tag | Migrar a `next-auth@4` (JWT) o a otra librería (por ejemplo Better Auth) si el beta da problemas en producción. Se instala recién en la Fase 1 |
| 2026-09-27 | TypeScript fijado en la serie `^5` (resuelve a 5.9.3) en vez de la 7.0.2 | `typescript-eslint` 8.x (la que trae `eslint-config-next@16`) declara `peerDependency: typescript >=4.8.4 <6.1.0`; TS 7 rompería el lint | Subir el rango en `package.json` cuando `typescript-eslint` soporte TS 7 |
| 2026-09-27 | Zod v4 (`4.6.5`) para todo el proyecto | Es la versión estable actual; `drizzle-zod` ya declara soporte (`peerDependencies: zod ^3.25 \|\| ^4`) | Bajar a Zod v3 si algún schema depende de la API vieja de errores (`.flatten()`, etc.) |
| 2026-09-27 | Driver de Postgres para Drizzle: `postgres` (postgres-js). La app usa `DATABASE_URL` (pooled) con `prepare: false`; `drizzle-kit` usa `DATABASE_URL_UNPOOLED` para migraciones | La URL pooled de Neon pasa por pgbouncer en modo transacción, que no soporta prepared statements; `drizzle-kit` necesita conexión directa para alterar el schema | Cambiar a `@neondatabase/serverless` si más adelante se necesita correr consultas en Edge Runtime |
| 2026-09-27 | `package.json` con `"type": "module"` | Next 16, Vitest, Playwright y Drizzle Kit ya son todos ESM; evita el warning de Vitest por cargar `vitest.config.ts` como CommonJS | Sacar el campo si algún script de terceros exige CommonJS |
| 2026-09-27 | `src/env.ts` valida con Zod las variables de `02-arquitectura.md` desde la Fase 0, pero solo `DATABASE_URL` y `DATABASE_URL_UNPOOLED` son obligatorias por ahora; el resto queda `.optional()` hasta que la fase que las usa exista en código (Auth.js, Resend, Vercel Blob, Mercado Pago) | Exigir ya variables de fases que todavía no tienen código (auth, pagos, email) bloquearía `pnpm dev`/`pnpm build` sin necesidad | Sacar el `.optional()` de cada variable a medida que se implementa su fase |
| 2026-10-06 | No usar `@react-email/components` (ni ningún `@react-email/*` de componentes); los emails son HTML plano en `src/lib/email/templates/` | Todos esos paquetes figuran deprecados en npm con el mensaje genérico "Package no longer supported. Contact Support" en su última versión, mientras `react-email` y `@react-email/render` siguen activos: patrón sospechoso de cadena de suministro | Reevaluar react-email cuando npm aclare el estado de los paquetes; solo cambia el armado del HTML, no el envío por Resend |
| 2026-10-06 | `src/proxy.ts` en vez de `src/middleware.ts` | Next.js 16 renombró la convención (`middleware` está deprecada); `proxy` corre siempre en runtime Node | — |
| 2026-10-06 | La resolución de tenant NO se cachea entre requests (solo `cache()` de React por request); `docs/02` sugería cache con tag `tenant:<id>` | Cada cambio de un admin se ve en el próximo request sin invalidar nada; el cache no es necesario hasta la Fase 7 (Lighthouse) | Envolver `getTenantByHost/BySlug` en `unstable_cache` con tags e invalidar con `revalidateTag` al editar la cámara |
| 2026-10-06 | Host firmado (HMAC) entre el proxy y el fetch interno de las server actions: el proxy firma `x-pc-host` en `x-pc-host-sig` (con `PREVIEW_SIGNING_SECRET`) y lo respeta solo si la firma valida | Tras un `redirect()` en una server action, Next hace un fetch interno a `localhost:<puerto>` reenviando los headers originales; sin esto el proxy leía `Host: localhost:3000` y la cámara se perdía (404). Un cliente externo no puede forjar la firma | Si Next deja de usar el origin del server para ese fetch (o se define `__NEXT_PRIVATE_ORIGIN`), se puede borrar `resolveRequestHost` |
| 2026-10-06 | `callbacks.redirect` propio en Auth.js: permite URLs absolutas solo si el host es un dominio de cámara real o de superadmin | El default solo acepta el origin de `baseUrl` y en un esquema multi-dominio mandaba al host genérico tras verificar el magic link; así no se abre un open-redirect | — |
| 2026-10-06 | La membership del primer login se crea en `events.signIn`, no en `callbacks.signIn` | El provider de email dispara `callbacks.signIn` antes de mandar el link con un `user` no persistido (violaba la FK a `users`) | — |
| 2026-10-06 | `email_log` + `sendEmail` loguea en consola/tabla cuando el destinatario es `*.demo` o no hay `RESEND_API_KEY` | `docs/09` lo pide para la demo; además permite probar el magic link en e2e leyendo el link de la tabla | Sacar la tabla si no se quiere el panel de "últimos emails" |
| 2026-10-06 | Empresas autodeclaradas (CUIT fuera del padrón) se crean con `legal_name = "Empresa <CUIT con guiones>"` | El onboarding solo pide CUIT; el admin completa la razón social después | — |
| 2026-10-06 | `alumno@ribera.demo` y `avanzado@ribera.demo` existen (no estaban en `docs/09`) y quedan `pending` en Ribera | `/demo` necesita un alumno fijo por cámara; en `cuit_email_domain` su dominio `ribera.demo` no coincide con el de la empresa, y es el comportamiento correcto del modo | Ajustar el dominio de la empresa seed si se quiere un alumno demo `verified` en Ribera |
| 2026-10-06 | Sin `server-only` en `tenant-scope.ts` y `tenant/membership.ts` | `scripts/seed.ts` los reusa fuera del bundler de Next, donde `server-only` siempre tira error | — |
| 2026-10-06 | Los logos SVG de demo (`public/demo/*.svg`, `docs/09`) quedan pendientes: las cámaras muestran su nombre como texto | No bloquea ningún criterio de la Fase 1 | Generar los SVG y cargar `logo_url` en el seed |
